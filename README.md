# 文渊 · 项目文件智能归档

> 原名「归档官」，v1.6 起改名为「文渊」。网站：https://jamesju1987.github.io/wenyuan/

把文件丢进「_收件箱」，系统自动识别它属于哪个客户、哪个项目、是什么交付物，按统一规范重命名后放进对应目录。拿不准的文件进入「待复核」，你确认一下即可。

## 快速开始（Mac）

1. 把整个「文渊」文件夹放到固定位置，例如 `~/workspace/文渊`。
2. 双击 **启动文渊.command**。首次运行会自动安装依赖（约 1 分钟），完成后浏览器打开 `http://127.0.0.1:8790`。
   - 如果提示「无法验证开发者」：在访达里右键该文件 →「打开」→ 再点「打开」，之后就能直接双击。
   - 也可以在终端运行：`bash ~/workspace/文渊/启动文渊.command`
3. 在「设置」里确认归档库位置（默认 `~/项目归档库`）。
4. 在「项目」里导入 CRM 导出的项目列表（Excel 或 CSV，可先「下载模板」看格式），或手动新建项目。
5. 之后把文件拖进网页，或直接放进 `~/项目归档库/_收件箱`，就会自动整理。

**想让它一直在后台工作**：双击 **设置开机自动运行.command**。之后登录 Mac 就自动运行，不需要开着终端窗口；取消时双击 **取消开机自动运行.command**。

> 需要 Python 3.9 及以上。终端里输入 `python3 --version` 可以查看；没有的话从 python.org 安装即可。

## 快速开始（Windows）

1. 把「文渊」文件夹放到固定位置，例如 `D:\工具\文渊`。
2. 双击 **启动文渊.bat**。首次运行会自动安装依赖，完成后浏览器打开 `http://127.0.0.1:8790`。
3. 之后文渊在**后台运行**，右下角托盘有图标，黑色窗口 5 秒后自动关闭：
   - 托盘图标右键：打开文渊、打开收件箱、暂停自动整理、开机自动运行、退出。
   - 处理完一批文件会弹通知：「自动归档了 3 个文件，2 个需要复核」。
   - 开始菜单里会出现「文渊」，以后从这里打开即可。
4. 在「设置 → 运行方式」里打开 **开机自动运行**。
5. 默认归档库在 `C:\Users\你的用户名\项目归档库`。

## 升级到新版本

1. 把新版压缩包解压，覆盖到原来的程序文件夹。
2. 重新双击启动，会自动关掉正在运行的旧版本。

**从「归档官」升级到「文渊」（v1.6）**：压缩包里的文件夹改叫「文渊」了。把它解压到旧「归档官」文件夹旁边（同一个上级文件夹里），双击「启动文渊」即可：

- 自动接着用旧文件夹里的数据（设置、项目、归档记录、学会的规则），只复制不改动旧数据；
- Windows 上旧的「发送到 → 归档官」、开始菜单和开机启动项自动换成「文渊」；
- Mac 设置过开机自动运行的，再双击一次「设置开机自动运行.command」。

确认一切正常后，旧的「归档官」文件夹可以删掉。

`data` 文件夹不在压缩包里，所以设置、项目、归档记录和已学会的规则都会保留。数据库结构有变化时，启动时会自动升级，不需要手动处理。

- v1.3 第一次启动时会自动安装「图片文字识别组件」（约 100 MB，只需一次，1–3 分钟）。没装上也能正常使用，下次启动会再试。
- v1.4 起 Windows 在后台运行：升级时直接覆盖再双击启动，会自动关掉旧版本换成新版本。从 v1.3 及更早版本升级时，旧版本是黑色命令行窗口，请先关掉它。
- Mac 设置了开机自动运行的，覆盖后双击「启动文渊.command」，会自动补装组件并重启后台服务。
- v1.4.1 起页面会自动加载新版本的界面，不用再按 Ctrl+F5。
- **请尽量覆盖到原来的文件夹**：新文件夹里没有 `data`，程序会从空数据库开始，重新导入 CRM 后客户编码会变，归档库里就会多出一套客户文件夹（见下面「整理重复的客户」）。v1.5.1 起即使解压到了新文件夹，也会自动接着用上一次的数据；v1.6 起旧程序文件夹放在旁边也能找到。

## 1.6.4：压缩包整包归档

- 压缩包默认不再拆开：解出几份文件看一眼，认出项目和类型后，整个压缩包按规范改名归档。详见下面「压缩包」。
- 原来的「解压后逐个归档」仍可在设置里选，或在卡片上对某一个包手动拆开。

## 1.6.3：DeepSeek 也参与判断

- 关键词拿不准项目或类型时（不到 90%），DeepSeek 会拿到全部候选项目清单和类型码，独立判断一次（不告诉它关键词的结论，避免跟着走），和标题、日期、摘要在同一次调用里完成，不多花时间。
- 主要提升三类文件：客户名只在正文里出现的（以前 84% 进待复核）、一个客户有好几个在建项目分不清的、文件名和正文都没写全称而用了简称或系统名的。
- 防止乱判：要求它摘抄原文依据，依据在文件里找不到、或说的不是这个客户，就不自动归档；和关键词结论冲突时压到 75% 交给你，它的选择会出现在复核的候选里。
- 设置 → DeepSeek →「也判断项目和类型」可以关掉；「测试连接」会顺便用两个虚构项目试一次判断，确认模型判断得对。

## 1.6.2 修复

- 微信、企业微信收到的文件卡在「识别中」：Windows 版微信（3.9 起）把收到的文件设成只读，文渊复制过来的临时副本删不掉，处理中途出错，记录就一直停在「识别中」。现在复制后会去掉只读，删不掉时会重试，处理中出任何意外都会标成「出错」，不会再卡住。
- 升级后第一次启动，以前卡在「识别中」的记录会自动重新处理；临时文件已经不在的，会如实标出来。
- 单个文件识别超过 5 分钟会跳过，交给你手动处理，不会堵住后面的文件。
- 以前从微信归档进来的文件如果是只读的（打开后不能直接保存），启动时会自动去掉只读。

## 整理重复的客户（v1.5.1）

归档库里同一个客户出现两个文件夹（比如「青岚医疗器械有_C0002」和「青岚医疗」），文件分散在两边，一般是这两种原因：

- **换过数据库**：新版本解压到了新文件夹，或者删过 `data`。重新导入 CRM 后客户简称、编码都变了，新文件夹建在旧文件夹旁边。旧文件夹在网页里显示为带编码的原名，里面的文件搜不到、版本也接不上。
- **同一客户写法不同**：CRM 里或手工新建项目时，同一个客户用了不同名称（全称、简称），被当成了两个客户。

整理方法：归档库页面顶部出现黄色提示时点「整理…」，或在「项目」里点「整理重复客户」。窗口里每组上面是保留的客户，下面是要并进去的文件夹或客户：

- 有把握的默认勾选：按项目编号能确定归属的旧文件夹、名称几乎一样的客户（只差地区或公司后缀）。拿不准的（比如「星衡能源」和「星衡新能源」）默认不勾，确认是同一家再勾上；两个客户都可以点「改为保留这个」换成保留另一个。
- 合并时项目文件夹放回各自的正式目录，其他文件放进保留客户的文件夹。文件只移动、不删除；两边内容完全相同的只留一份，同名但内容不同的加编号（如 `-2`）保留。
- 被并入的客户名称自动记为别名，以后 CRM 再导入这个名称会直接归到保留的客户，不会再建一个。
- 勾选「补登记」后，按规范命名但数据库里没有记录的文件会重新登记：能搜到，版本号也能接上（比如旧文件夹里已有 V1.1，下次归档就是 V1.2）。
- 没有对应客户的文件夹（比如你自己放进来的资料）默认不处理，也可以选择并入某个客户。
- 有文件正被 Word 等程序打开时会移不动，关掉后再整理一次即可。

另外，导入 CRM 或新建项目时，如果归档库里已经有同一项目编号的文件夹，会自动并到这个项目的目录里，不再新建。

## 归档库结构

```
项目归档库/
├── _收件箱/            统一投放入口（可整个文件夹拖进来，同一批文件互相参考归属）
├── _待复核/            项目找到了，但类型或归属拿不准
├── _未匹配/            没找到对应项目
├── _重复文件/          内容完全相同的文件（按 SHA-256 判断，不删除）
├── _原始压缩包/        解压后的原压缩包，按月份存放
├── 澄湾科技_C0001/                       一级：客户简称_客户编码
│   └── PRJ-2026-0123_等保测评2026/       二级：项目编号_项目简称
│       ├── 00_项目管理  01_售前商务  02_项目启动
│       ├── 03_过程文档/证据/              截图、扫描结果按批次存放，保留原名
│       ├── 04_交付成果  05_验收结项  06_客户资料
│       ├── _历史版本/                     被新版本替代的旧文件
│       └── _归档包/                       结项时一键生成的 ZIP + 清单
```

## 命名规范

```
{项目编号}_{类型码}_{文档标题}_{版本}_{状态}_{日期}.{扩展名}
PRJ-2026-0123_RPT-DJ_澄湾科技等保测评报告_V1.1_正式_20261016.docx
```

- 标题：客户简称 + 内容主题，≤ 30 字，自动去掉「最终版」「(2)」「修改版」等噪声。
- 版本：草稿/内审/送审 为 V0.x；首次正式 V1.0；之后每次修改 V1.1、V1.2…，旧版自动移入 `_历史版本`。
- 状态：草稿 / 内审 / 送审 / 正式 / 签字。
- 内置 31 个类型码（RPT-DJ 等保测评报告、KO-AUTH 测试授权书…），在「设置 → 命名规范 → 交付物类型 → 查看全部」里可查看。
- 对外发送时，在归档库里选中文件 → 复制「对外交付名」（去掉内部编号和类型码）。

### 新增交付物类型（v1.5）

内置类型不够用时（比如「服务生效单」「应急响应报告」），可以自己加。有两个入口：

- **复核时现加**：在待复核卡片的「类型」框里输入名称，找不到时列表最下面会出现「新增类型「服务生效单」…」，点它填好目录就能用，当前这份文件直接选上。
- **设置里加**：设置 → 命名规范 → 交付物类型 →「新增类型」。

需要填写的内容：

| 项 | 说明 |
|---|---|
| 类型名称 | 2–20 个字，会出现在选择框和归档库里 |
| 归档目录 | 放进哪个阶段目录（00_项目管理 … 06_客户资料，或 03_过程文档/证据） |
| 类型码 | 按目录和名称自动生成（如 `KO-FWSXD`），可以改；保存后不能再改，因为它会写进文件名 |
| 识别关键词 | 文件名或正文里出现这些词就判为这个类型，用顿号隔开；类型名称本身自动算一个 |
| 每份单独存放 | 勾上后同类文件互不替代版本（适合周报、纪要这类每期一份的文件） |

新类型保存后立刻参与识别，下一个文件就能自动归到它。

- **内置类型加关键词**：内置类型的名称和目录不能改，但可以点「加词」追加你们自己的叫法（比如给「验收单」加上「系统上线确认」）。
- **停用和删除**：自定义类型还没有文件和规则在用时可以直接删除；已经在用就只能「停用」。停用后它不再参与识别、不出现在选择框里，已归档的文件照常显示原名称，随时可以重新启用。

## 识别是怎么做的

1. **关键词快判（本地，毫秒级）**：文件名、文件夹、正文开头里的项目编号、客户名称/别名、类型关键词。项目编号出现就直接锁定。图片和扫描件先在本机识别出文字（见「图片与扫描件」）。
2. **Jev 快速判断（可选）**：关键词判断不了或有冲突时，让 Jev 在候选项目和类型码里做选择题，返回概率。
3. **DeepSeek 内容分析（可选）**：读正文开头，生成规范标题、内容日期和一句话摘要。关键词拿不准时，还会在候选项目和类型码里独立判断一次（v1.6.3，可在设置里关掉）。
4. **置信度分流**：综合把握 ≥ 90% 自动归档；项目有把握但其他字段拿不准进「待复核」；没找到项目进「未匹配」。阈值可在设置里调。
5. **越用越准**：见下面「持续学习」。

不配置任何 API Key 也能用（只用关键词）；配置后在「设置」里打开开关并点「测试连接」。

### 把握是怎么算的（v1.6.2）

每个文件分别给「项目」和「类型」打一个把握，**综合把握取两者里较低的一个**：项目再有把握，类型拿不准也不会自动归档。它不是几种方法按比例加权，而是一层层判断，后面的层只在前面拿不准时出手：

| 依据 | 项目把握 | 类型把握 |
|---|---|---|
| 上传时指定项目 / 出现项目编号 | 100% | — |
| 记住的规则、自动学习的规则 | 97% | 85%～95% |
| 客户名在文件名里 / 只在正文里 | 95% / 84%（客户有多个在建项目时再靠项目简称区分，分不清只给 65%～70%） | — |
| 同一批次的其他文件已归入某项目 | 90%～92% | — |
| 类型关键词在文件名里 / 只在正文里 | — | 85%～95%（文件名里同时有几种类型词时更低）/ 45%～80% |
| 历史上相似的文件 | 结论一致再加 4%，不一致压到 78% 以下 | 同左 |
| Jev（可选，关键词不到 90% 时才问） | 与关键词一致提到 93% 以上，不一致压到 75% | 同左 |
| DeepSeek（可选，关键词不到 90% 时才判断） | 一致 → 92%；认出客户但分不清项目时由它挑 → 90%；关键词认不出、它认出且给的原文依据对得上 → 90%，对不上最多 80%；不一致 → 压到 75% | 一致 → 92%；关键词没认出或只是正文零星命中、它有九成把握 → 90%；和文件名里的类型词冲突 → 压到 75% |

综合把握 ≥ 90% 自动归档；项目把握 ≥ 60% 进「待复核」；更低进「未匹配」。

- 「最近处理」和「处理记录」里每条都显示把握，鼠标停在上面能看到项目、类型各自的把握和依据（如「客户名（文件名） + 历史印证」）。
- 已经有分歧的（如 Jev 和关键词不一致），DeepSeek 再同意其中一方也只到 85%，仍请你确认。
- 方法标签：「关键词+DeepSeek」= 关键词定的、DeepSeek 印证或帮忙区分；「DeepSeek」= 关键词认不出、由 DeepSeek 认出来的。只用 DeepSeek 起标题的仍记为「关键词」。
- 概览「自动归档率」上停一下，能看到已归档的文件分别靠关键词、Jev、人工确认归档的个数和比例。

- Jev：`console.typesafe.ai` 创建 Key，接口 `https://api.typesafe.ai/v1/systemone`，模型 `jev-latest`。
- DeepSeek：`platform.deepseek.com` 创建 Key，模型 `deepseek-v4-flash`。
- 发给模型的只有文件名和正文开头（默认 1500 字），原文件不上传。Jev 和 DeepSeek 判断项目时，还会收到候选项目清单（项目编号、客户名称、项目名称、业务线）。

## 持续学习（v1.2）

你在待复核里每确认一次，系统都会记下来，不需要额外操作：

- **参考历史归档**：新文件先和已归档文件比对文件名与正文开头。和以前的文件很像（每周的周报、同一系统的系列报告），就直接沿用上次的项目和类型。
- **自动生成规则**：同一个特征词（如「ERP门户」）被你确认了 2 次，且都归到同一个项目，就自动生成项目规则，第 3 个文件直接归档。同一个叫法（如「安测报告」）在不同项目里都被你定为同一类型，就生成类型规则。确认后右上角会提示「学会了一条新规则」。
- **自动纠错**：自动规则判错、你手动改正后，这条规则会自动停用，不会一错再错。
- **手动规则**：确认时填「记住规则：文件名包含 XX」，效果相同，优先级更高。
- **查看与管理**：「项目」页底部「已学会的规则」，可以停用或删除。设置 →「持续学习」里可以关闭，也能改「生成规则所需次数」（越大越稳）。

一个客户有多个几乎一样的项目时（如同名的渗透漏扫项目），类型规则会帮你填好类型，但项目仍会请你选一下，避免归错。

## 文件怎么进来（v1.4）

| 方式 | 怎么用 | 原文件 |
|---|---|---|
| 收件箱 | 把文件或整个文件夹拖进 `_收件箱` | 移走归档 |
| 网页 | 拖到网页上，可先选「归档到」某个项目 | 上传一份 |
| 右键发送（Windows） | 在资源管理器里选中文件或文件夹 → 右键 →「发送到」→「文渊」 | 默认保留，可在设置里改为移走 |
| 微信 / 企业微信 | 设置 →「文件来源」→「自动查找微信 / 企业微信」 | 只复制，不动原文件 |
| 压缩包 | 上面任何一种方式进来的 zip、7z、rar、tar：看里面的文件认项目，整包改名归档（也可设成解压后逐个归档） | 整包归档 |

### 微信、企业微信

- 只收**开启之后**新收到的文件，以前的历史文件不管。每个文件只收一次。
- 只收文档、图片、压缩包，安装包、视频、聊天缓存不收。
- 微信里也有私人文件：认不出属于哪个项目的默认**忽略**（在「处理记录 → 已忽略」里能看到，需要时点「拿来归档」）。也可以改成放进「未匹配」。
- 已经归档过的同一个文件（比如你先拖进来过）会自动跳过，不会重复。
- 请在微信「设置 → 文件管理」里打开文件自动下载，收到的文件才会自动存到电脑上。聊天里的图片要「以文件形式」发送才会被收进来。
- 「自动查找」会看：文档文件夹、微信自己记下的存储位置（新版和旧版微信都看），以及每个硬盘根目录和第一层文件夹里的「WeChat Files」「xwechat_files」「WXWork」。每个登录过的账号各添加一个来源。
- 还是找不到时，点「添加文件夹…」手动选。位置在微信「设置 → 文件管理」里点「打开文件夹」就能看到。选「WeChat Files」「xwechat_files」「WXWork」这一层（或者里面任意一层）都行，会自动换成每个账号收文件的那个文件夹（新版微信是 `…\msg\file`，旧版是 `…\FileStorage\File`）。
- 也可以把「下载」文件夹当来源，适合浏览器下载的客户资料。

### 压缩包

默认**整包归档**（v1.6.4 起）：不拆开压缩包，只解出里面几份有代表性的文档（Word、PDF、PPT、Excel 优先，没有文档就看一张图片）读一读，判断属于哪个项目、什么类型，然后整个压缩包按命名规范改名，放进对应阶段目录。临时解出的文件读完就删，压缩包本身原样归档。

- **项目**：压缩包名字、里面的文件名、读到的正文一起判断，和普通文件一样会用到规则、历史、Jev、DeepSeek。
- **类型**：压缩包名字写明了的为准（如「渗透测试报告及附件.zip」）；否则看里面的文件，按大小算主文件是什么（「报告 + 附件」按报告算）；大部分是图片的按截图证据、像扫描结果的按扫描原始结果；类型很杂、分属不同阶段的进待复核。
- **标题**：压缩包名字只是「资料」「附件」「加密资料」之类时，用里面主要文件的名字。双后缀不会丢（`.tar.gz`）。
- **加密包**：先自动试「记住的密码」。zip、7z 加密后通常还能看到里面的文件名，靠文件名能认出来就直接整包归档，不用密码；认不出来的进待复核，在卡片上输入密码点「用密码识别」，勾选「记住」以后自动用。
- 微信来的压缩包认不出项目的，和其他文件一样忽略（有密码的除外，会留给你输密码）。
- 想拆开时：待复核卡片上点「解压后逐个归档」；或者在设置 →「压缩包怎么归档」里改成「解压后逐个归档」，回到以前的方式（文件不多的包解压后逐个识别，扫描结果包、文件很多的包仍整包归档）。
- Windows 自带压缩软件打包的中文文件名会自动还原，不会乱码。
- rar 需要本机装有 7-Zip（免费）或 WinRAR。没有时只按名称判断。

## 图片与扫描件（v1.3）

图片和扫描版 PDF 会先在本机识别图中文字（RapidOCR，离线，不上传），再按内容归档：

| 文件 | 怎么处理 |
|---|---|
| 授权书、验收单、合同的**照片**（如「微信图片_xxx.jpg」） | 读出标题「网络安全渗透测试授权书」→ 按测试授权书命名，状态默认「签字」，归入 `02_项目启动` |
| **扫描版 PDF**（扫描全能王、扫描仪） | 识别前 2 页，标题行决定类型，日期取「日期：」后的落款日期 |
| 系统/漏洞**截图** | 仍是截图证据，保留原文件名；图里出现客户名称或域名时用来找项目 |
| 有文字层的普通 PDF | 和以前一样直接读文字，不走识别 |

- 怎么区分「文件照片」和「截图」：文件名里有截图、截屏、Snipaste、漏洞等字样，一定按截图处理。否则看图中第一行是不是文件标题（授权书、确认单…），再参考横竖构图、网址、请求包等特征。
- 速度：每张图 1–3 秒，扫描 PDF 每页 1–3 秒，第一次识别要多花几秒加载模型。
- 设置 →「图片与扫描件」：可以关闭识别、修改 PDF 识别页数，点「测试识别」确认组件正常。
- 截图找项目的小技巧：在客户别名里加上客户的域名关键字（如 `starbucks`、`sphchina`），截图里的网址就能对上客户。
- iPhone 的 HEIC 照片需要可选组件 pillow-heif，安装脚本会自动尝试安装；装不上时把照片导出为 JPG 即可。

识别出的结果默认进入「待复核」，内容都已填好，确认无误按回车即可。文件名带项目编号或命中规则时会直接归档。

## 快速查找（模糊检索）

- **项目、类型选择框**：点开后直接打字筛选，支持：
  - 关键字：`青岚`、`等保`。
  - 拼音首字母：`qlyl` 找到「青岚医疗」，`dbcp` 找到「等保测评报告」。
  - 项目编号片段：`0123`。
  - 多个词用空格分开：`qlyl 等保`。

  用 ↑↓ 选择，回车确定，Esc 取消。中文输入法没切到英文时直接打 `qlyl` 也能筛选。
- **项目页筛选框**：同样支持关键字、拼音首字母和编号片段，匹配到的字会标亮。
- **顶部搜索（⌘F / Ctrl F）**：按文件名、标题、项目、客户、类型查找，允许中间隔字，例如「澄湾等保」能找到「澄湾科技等保测评报告」。全局搜索不支持拼音首字母。

## 提升识别率的小技巧

- 给客户填好别名（如「澄湾」「CW」），文件里常出现哪种叫法就填哪种。
- 同一客户有多个在建项目时，给项目填「业务线」和「项目关键词」（系统名称、IP 段等）。
- 整批文件放在一个文件夹里拖进 `_收件箱`，第一个文件识别出项目后，同批其他文件会参考它。
- 网页上拖入文件时可以先选「归档到」某个项目，这批文件就不用再判断归属。

## 常见问题

- **撤销**：概览或处理记录里，已归档的文件右侧有撤销按钮；文件回到 `_待复核`，被替代的旧版本恢复原位。
- **待处理的文件被改名了**：可以直接在访达/资源管理器里改名，系统会按文件内容找到它，照常归档；点「重新识别」会按新名字重新判断。
- **不想处理某个文件**：在卡片上点「移出列表」，它不再出现在待复核/未匹配里，文件本身保留在原文件夹。
- **公司内部资料（产品方案、模板等）**：建议建一个内部项目，例如客户「公司内部」、项目「产品方案库」，这类文件也能按规范归档和检索。
- **编辑项目**：在「项目」里点任意一行即可编辑；项目多时用上方的筛选框按编号、客户或名称查找。
- **修改客户/项目简称**：在「项目」里编辑，目录会同步改名，已归档文件的记录跟着更新。
- **更换归档库位置**：先在访达里把整个文件夹移过去，再在设置里选新位置。
- **归档库放在「文稿」「桌面」里**：开机自动运行模式下，macOS 可能需要在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」里允许 Python；放在用户目录下（默认）则不需要。
- **同一个客户有两个文件夹**：见「整理重复的客户」。
- **数据在哪**：设置和数据库在本程序的 `data/` 文件夹里，日志在 `data/server.log`。服务只监听本机 127.0.0.1，外部访问不到；改动类请求要带专用标记，别的网页没法冒充你操作。
- **怎么退出**：Windows 在托盘图标右键 →「退出文渊」；任何系统都可以在「设置 → 运行方式」里点「退出」。
- **托盘图标不见了**：可能被收进了任务栏的「^」里，可以拖出来常驻。实在没有托盘时文渊仍在后台运行，从开始菜单打开即可。
- **右键菜单里没有「文渊」**：在「设置 → 运行方式」里把「右键发送到」关掉再打开一次。
